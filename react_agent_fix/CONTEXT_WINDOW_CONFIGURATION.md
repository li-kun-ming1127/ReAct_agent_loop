# 上下文窗口与长期记忆配置

## 推荐默认值

| 环境变量 | 默认值 | 作用 |
| --- | ---: | --- |
| `MODEL_CONTEXT_TOKENS` | 131072 | 应用采用的工作窗口；不等同于模型供应商公布的理论上限。 |
| `CONTEXT_INPUT_BUDGET_TOKENS` | 106496 | 单次模型调用中，系统提示、摘要、对话、工具结果和工具定义的总输入预算。 |
| `OUTPUT_RESERVE_TOKENS` | 8192 | 模型回答上限，同时从上下文窗口中预留。 |
| `CONTEXT_SAFETY_MARGIN_TOKENS` | 8192 | 抵御估算误差、协议包装和供应商计数差异。 |
| `SYSTEM_RESERVE_TOKENS` | 8192 | 为动态 system、工具 schema 和未来多 Agent 路由提示预留。 |
| `HISTORY_TARGET_TOKENS` | 65536 | Redis 中保留的近期完整对话轮次目标。超过后摘要旧轮次。 |
| `SUMMARY_INPUT_TOKENS` | 12000 | 单次摘要合并输入上限。 |
| `SUMMARY_OUTPUT_TOKENS` | 2048 | 历史摘要输出上限。 |
| `MAX_HISTORY_MESSAGES` | 80 | token 阈值之外的消息数量保险阈值。 |
| `MIN_RECENT_TURNS` | 2 | 常规压缩至少保留的最近完整轮次；硬预算不足时仍至少保留当前完整轮次。 |
| `MAX_TOOL_MESSAGE_TOKENS` | 12000 | 单条工具返回进入模型上下文的上限。保留头尾且不破坏 `tool_call_id`。 |
| `TOKEN_ESTIMATE_CHARS_PER_TOKEN` | 3.0 | 中英文混合内容的保守近似值。 |

默认输入预算为：

`131072 - 8192（输出）- 8192（安全）- 8192（system/工具预留）= 106496`

代码会自动钳制不合理的环境变量：输入预算不会超过工作窗口可用值，Redis 历史目标不会超过输入预算。

## 数据库、工具和多 Agent 扩展

- PDF 或向量库文件变大，不应直接提高上下文预算。数据库规模影响索引和召回，真正进入上下文的只应是检索后的少量文档。优先控制 RAG 的 `top_k`、单文档长度、去重和重排。
- 工具增加时，工具 schema 本身会占 token。本实现把当前 `tools` 定义加入每次预算估算，因此工具数量增加会自动减少可用历史空间。
- 多 Agent 协作时，不要把所有子 Agent 的完整轨迹都传给主 Agent。子 Agent 应返回结构化结论、证据来源和短摘要；主 Agent 只保存这些交接结果。
- 当工具超过约 20 个、system 提示明显增长，或多个 Agent 的交接结果同时进入上下文时，可先把 `MODEL_CONTEXT_TOKENS` 提高到 262144，并保持至少 16384 的安全余量；应先用真实请求测量延迟和费用，再扩大到更高窗口。
- `MAX_TOOL_MESSAGE_TOKENS=12000` 是单条工具结果上限，不是每轮所有工具结果的总上限。工具链较多时建议将其降到 6000-8000，并让工具返回摘要加文档 ID，而不是整份原文。

## 记忆语义

持久化长期记忆由两部分构成：

1. Redis 中的近期完整对话轮次，默认目标 65536 token，TTL 默认 7 天。
2. 被淘汰旧轮次的滚动摘要，按当前用户、浏览器会话和知识库隔离存储。

每次调用模型前还会执行一次硬预算检查。它按完整轮次移除最旧内容，并把本次临时移出的轮次与既有摘要合并后注入模型；回答完成后，Redis 压缩再把达到持久化阈值的旧轮次正式写入摘要。动态角色 `system` 提示始终是第一条消息。
